# Політика безпеки

## Підтримувані версії

uPyth наразі розвивається як єдина активна лінія версій (остання —
дивіться `CHANGELOG.md` / `package.json`). Оновлення безпеки виходять
для найновішої версії; окремі старі релізи назад не патчаться.

## Як повідомити про вразливість

Якщо ви знайшли проблему безпеки (наприклад, спосіб виконати довільний
код через збережений `.xml`-проєкт, XSS через дані, що потрапляють у
вивід/панель Pico, або щось подібне) — **не публікуйте деталі у
відкритому Issue**, доки проблему не буде виправлено.

Способи повідомити приватно:

1. **Пріоритетно:** [GitHub Security Advisories](https://github.com/kseryi/uPyth/security/advisories/new)
   для репозиторію https://github.com/kseryi/uPyth — приватний канал,
   бачить лише супровідник, поки ви самі не розкриєте деталі публічно.
2. Якщо GitHub Security Advisories з якоїсь причини недоступний —
   відкрийте звичайний [Issue](https://github.com/kseryi/uPyth/issues)
   з позначкою "security" і **без технічних деталей експлойту**,
   попросивши зв'язатись приватно; супровідник відповість з проханням
   надіслати деталі закритим каналом.

## Чого очікувати

- Підтвердження отримання — орієнтовно протягом кількох днів (проєкт
  підтримується однією людиною, не корпоративною командою — чесно
  попереджаємо про це наперед).
- Після підтвердження й виправлення — координоване розкриття: зміна
  публікується разом з описом у `CHANGELOG.md`, а автору звіту (за
  бажанням) — подяка в тому ж записі.

## Що вважається вразливістю в контексті uPyth

Проєкт — клієнтське середовище виконання коду в браузері (Blockly +
Skulpt), розраховане на локальне/шкільне використання. Особливо цікаві
звіти про:
- будь-який спосіб, яким збережений `.xml`-проєкт або введений у блоки
  текст призводить до виконання довільного JavaScript у сторінці (XSS);
- проблеми в модулі Raspberry Pi Pico (`js/extensions/pico.js`), що
  дозволяють відправити на плату команди, які користувач явно не
  запускав.

"Учнівський" Python-код, що виконується через Skulpt у пісочниці
браузера самого користувача, — це очікувана поведінка середовища
програмування, а не вразливість сама по собі.
