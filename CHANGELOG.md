# v0.1.7 — Дизайн під референсний макет, ресайз панелей мишею

## 🎨 Дизайн панелі команд (toolbox) під референсний макет
- Панель категорій зліва ("1) Блоки") перероблена з дефолтного
  горизонтального списку Blockly на вертикальну колонку карток
  "іконка над підписом" — CSS-перевизначення офіційних класів
  Blockly-toolbox (`.blocklyToolboxCategoryContainer`,
  `.blocklyToolboxCategoryIcon`, `.blocklyToolboxCategoryLabel`,
  `.blocklyToolboxSelected`), без зміни самої логіки Blockly.
- Колір теми toolbox (`MyTheme` у `workspace.js`) змінено з яскраво-
  синього фону/жовтого тексту на темний фон/світлий текст, що збігається
  з рештою панелей; активна категорія — підсвічена акцентним синім.
- Кнопка **"▶ Запустити"** — суцільна акцентна синя "пігулка" замість
  однакової темної кнопки з рамкою, як і решта.

  функціонал лишився в коді, просто приховано через CSS), вирівнювання
  правої групи кнопок ("Уроки"/"?"/мова) виправлено відповідно.
- **Кнопки перемикання панелей** ("Сховати блоки"/"Сховати код"/"Сховати
  вивід") лишені навмисно нейтральними — лише текст перемикається між
  "Сховати"/"Показати", без додаткової кольорової заливки (за рішенням
  після перегляду проміжного варіанту з акцентним підсвічуванням).

## ↔️ Ресайз панелей мишею (нова можливість)

  прихована при переробці дизайну) — усі три панелі знову можна ховати

  vendored, середовище працює повністю офлайн".

### Raspberry Pi Pico: автовизначення браузера + підготовлений місток для агента
- Web Serial API (потрібен для підключення плати) підтримується лише в
  Chrome/Edge — це відоме обмеження тепер **задокументоване** в
  `README.md`/`NOTICE.md`, а не приховане.
- `js/extensions/pico.js`: додано перевірку `WEB_SERIAL_SUPPORTED`
  (`'serial' in navigator`) при відкритті панелі Pico. У Chrome/Edge
  усе працює як раніше (напряму через Web Serial). У Firefox/Safari та
  інших браузерах панель показує помітне попередження і кнопка

- Доданий клас `PicoAgentBridge` — архітектурний "стик" під майбутнє
  підключення через легку локальну Python-програму (`pyserial` +

  Windows/Linux/macOS) — окрема задача розвитку, чесно зафіксована як
  такий у `NOTICE.md`; `PicoAgentBridge.connect()` наразі прозоро

# v0.1.5 — Розширення (Tkinter) + стилізоване меню мови + мультимовність (UA/EN)

## 🧩 Система розширень + розширення "Tkinter (вікна)"

- **Кнопка "➕"** (синій кружечок) внизу праворуч панелі блоків відкриває
  список доступних розширень з чекбоксами.
- **Реалізовано через окремі js-файли**, як і просили:
  `js/extensions.js` — каталог + кнопка "➕" + механізм динамічного
  підключення; `js/extensions/tkinter.js` — саме розширення (блоки +
  генератор Python + попередній перегляд).
- Розширення підключається **динамічно** (`<script>` вставляється в
  сторінку лише при вмиканні), а не одразу при завантаженні сторінки.
- Увімкнені розширення **зберігаються** (localStorage) — після
  перезавантаження сторінки лишаються увімкненими.
- **Блоки Tkinter:** створити вікно (назва, розмір), додати напис,
  додати кнопку (з викликом функції), додати текстове поле, показати
  вікно. Генерують **справжній, коректний Python/tkinter-код**.

### ⚠️ Важлива технічна чесність
Виконання Python у браузері йде через Skulpt, а **Skulpt не підтримує
Tkinter** (справжні вікна ОС неможливо відтворити у вкладці браузера).
Тому кнопка "▶ Run" для коду з `import tkinter` показує **попередній
перегляд** — візуальний макет вікна (заголовок/написи/кнопки/поля),
намальований прямо в зоні, де зазвичай малює черепашка, чесно позначений
banner'ом як симуляція. Сам згенерований Python-код — справжній: якщо
скопіювати кнопкою "⬇ .py" і відкрити на комп'ютері (Thonny/IDLE) —
вікно з'явиться по-справжньому. Перевірено в реальному браузері: код
генерується коректно, макет відображається з правильними даними,
клік по кнопці в макеті показує пояснення.

## 🎨 Стилізація спадного меню мови

Меню вибору мови (раніше — стандартний білий `<select>` браузера) тепер
оформлене під загальну темну палітру середовища: темний фон, власна
стрілочка, кольори при наведенні/фокусі — як у решти кнопок.

## ✨ Нова категорія "Масиви" (Arrays/Lists)

Додано категорію "Масиви" з блоком **"create list with"**
(`lists_create_with`) — це вбудований блок Blockly з "комірками та
плюсиком": іконка-шестерня відкриває міні-редактор, де можна натисканням
+/− додати чи прибрати комірки-елементи списку, і в кожну підключити
будь-який блок-значення (число, текст, вираз). Також додано операції над
списками: довжина (`lists_length`), перевірка на порожність
(`lists_isEmpty`), отримати/змінити елемент за номером
(`lists_getIndex`/`lists_setIndex`), пошук елемента (`lists_indexOf`).
Перевірено в реальному браузері: коректно генерує `[10, 20, 30, 40]`,
`item[(2) - 1]`, `len(item)`; усі 11 категорій toolbox продовжують
відображатись без збоїв.

Детальний покроковий алгоритм цього прикладу — у
`HOW_TO_ADD_BLOCKS.md`, розділ "Приклад 2".

## 🐞 Виправлено (за повторним зверненням): текст "сам рухався" під час набору

Попередній фікс (синхронізація по Enter) прибрав перехід по таймеру, але
лишався прихований дефект: під час `applyCodeToBlocks()` виклик
`workspace.clear()` **тимчасово** запускав `refreshCode()` на ще
ПОРОЖНІЙ робочій області (до того, як нові блоки встигали
завантажитись). Це псувало збережену позицію курсора в текстовому полі
коду. Коли користувач одразу після Enter продовжував друкувати наступний
рядок, символи потрапляли не в те місце — виглядало так, ніби текст
"сам пересувається". Підтверджено тестом: рядок `t.forward(50)`,
набраний по символу одразу після Enter, ставав `.forward(50)` (перша
літера губилась/зміщувалась).

**Виправлення:** доданий прапорець `suppressAutoRefresh`, який на час
`workspace.clear()` + `domToWorkspace()` вимикає автоматичні проміжні
виклики `refreshCode()`; фінальне оновлення коду відбувається один раз,
явно, вже після того як усі блоки завантажені. Застосовано послідовно у
всіх місцях масового перезавантаження блоків (синхронізація код→блоки,
Example, Load .xml). Перевірено посимвольним набором тексту в реальному
браузері — жодних зсувів не залишилось.

## 🐞 Знайдений і виправлений баг: блоки в категоріях переставали відображатись

**Причина (підтверджено прямим тестуванням у headless-браузері, 80+ кліків
по категоріях):** у категорію "Pen" був доданий блок `colour_picker`
(візуальний вибір кольору) — але в цій конкретній збірці `blockly.min.js`
**немає модуля "colour"** взагалі (`Blockly.Blocks['colour_picker']` не
існує). Щойно Blockly намагався відрендерити цей неіснуючий тип у
flyout-панелі, він кидав виняток `Invalid block definition for type:
colour_picker`. Цей виняток стається ВСЕРЕДИНІ внутрішнього коду
рендерингу Blockly і **ламає внутрішній стан flyout** — після цього
панель команд для БУДЬ-якої категорії (не тільки "Pen") переставала
показувати блоки.

**Виправлення:** прибрано `colour_picker` з toolbox і з коду. Перевірено:
80 кліків по всіх 10 категоріях поспіль — блоки стабільно відображаються
у кожній.

**Загальний висновок (див. `HOW_TO_ADD_BLOCKS.md`):** ця збірка Blockly —
не повна, у ній бракує деяких стандартних модулів. Перш ніж додавати
"вбудований" тип блоку, якого раніше не було в проєкті, варто перевірити
`grep -c "тип_блоку" js/blockly.min.js` — якщо `0`, блоку немає в збірці.

## 🐞 Ще 2 баги, знайдені під час тестування цього виправлення

- **`applyCodeToBlocks` (синхронізація код→блоки) не оновлювала текстове
  поле коду.** Blockly групує/призупиняє події під час масового
  завантаження блоків з XML (`domToWorkspace`), тому наш
  `workspace.addChangeListener` не завжди надійно спрацьовував одразу
  після завантаження — код лишався застарілим ("# add blocks"), хоча
  блоки насправді оновлювались. Виправлено явним викликом `refreshCode()`
  одразу після `domToWorkspace`.
- **`Sk` (Skulpt) міг кидати `ReferenceError` замість акуратної
  обробки**, якщо CDN-скрипт не завантажився: `if (Sk && ...)` кидає
  помилку для НЕОГОЛОШЕНОЇ змінної (на відміну від `if (window.Sk && ...)`
  чи `typeof Sk !== 'undefined'`). Через це кнопка "▶ Run" могла мовчки
  "не працювати" без жодного повідомлення. Тепер є явна перевірка і
  зрозуміле повідомлення користувачу, якщо Skulpt недоступний.

## ✨ Нове

- **Синхронізація код→блоки тепер по Enter, а не по таймеру.** Раніше
  блоки перебудовувались автоматично через ~0.9с паузи в наборі тексту —
  це виглядало як мимовільний "перехід на новий рядок"/переформатування

## Виправлення надійності Web Serial (Pico) після реального тесту через localhost

Спостереження: підключення пройшло успішно, список файлів оновився, але
завантаження коду ("Upload") впало в тайм-аут. Оскільки перевірити на
фізичній платі в цьому середовищі неможливо, додав кілька захисних
покращень, які типово усувають саме такий симптом ("порт відкрився, але
плата мовчить"):

1. **DTR/RTS сигнали** виставляються одразу після відкриття порту
   (`port.setSignals(...)`) — на Linux деякі USB-CDC пристрої не починають
   передавати дані, доки ці сигнали не встановлено.
2. **Одна тиха повторна спроба** входу в raw REPL при першому тайм-ауті —
   усуває типові транзиторні гонки одразу після підключення.
3. **Детальніше повідомлення про тайм-аут** — тепер підказує перевірити
   правильність обраного порту, прошивку (MicroPython, не CircuitPython) і
   спробувати апаратний RESET.
4. **Автоматичне визначення фізичного від'єднання** плати (через
   `navigator.serial` / завершення циклу читання) — статус і кнопка більше
   не "зависають" у стані "підключено".

Якщо тайм-аут повториться навіть із цими фіксами — найімовірніше, порт у
списку вибору браузера відповідає НЕ платі Pico (напр. інший USB-пристрій),
або на платі не прошито MicroPython (заводська прошивка Pico з коробки —
не MicroPython, її потрібно прошити окремо, UF2-файл з micropython.org).

## Діагностика "OSError: Read-only filesystem" (Pico)

Ця помилка при спробі записати файл — майже завжди наслідок того, що на
платі встановлено **CircuitPython, а не MicroPython** (CircuitPython не
дозволяє запис файлів через REPL, лише через USB-диск CIRCUITPY; блоки
цього інструменту розраховані на MicroPython, модуль `machine`).

Додано:
- **Автоматична перевірка прошивки** одразу після підключення
  (`sys.implementation.name`) — статус покаже "🟡 Підключено (виявлено:
  circuitpython, не MicroPython!)", якщо це не MicroPython, і одразу
  пояснить проблему в консолі виводу, ДО спроби завантаження коду.
- **Пояснення прямо в тексті помилки** — якщо REPL все ж повертає
  "Read-only filesystem", повідомлення тепер одразу підказує ймовірну
  причину й посилання на UF2 з micropython.org/download/RPI_PICO/.

## Виправлення: "тайм-аут" при запуску файлу з безкінечним циклом на Pico

Насправді код на платі виконувався коректно (світлодіод блимав) — тайм-
аут виникав тому, що "▶ Run" через raw REPL ЧЕКАЄ сигналу завершення
скрипту, а `while True:` ніколи не завершується. Це не помилка мого
клієнта, а особливість протоколу — але повідомлення виглядало як помилка.

Додано:
- **"⏹ Перервати"** — надсилає Ctrl-C, коректно зупиняє те, що зараз
  виконується на платі (навіть безкінечний цикл), одразу з інтерфейсу.
- **"🔁 Назавжди"** для кожного файлу — ПРАВИЛЬНИЙ спосіб запустити
  програму з безкінечним циклом: м'який перезапуск плати (Ctrl-D у
  дружньому REPL, як фізичний RESET) — плата виконує файл самостійно,
  незалежно від з'єднання з браузером, без очікування завершення.
- Повідомлення при тайм-ауті тепер пояснює, що це очікувано для
  безкінечних циклів, а не показує це як помилку.

## "▶ Run" тепер стрімить вивід у реальному часі + спрощення (прибрано "🔁 Назавжди")

На запитання "чому не можна отримати результат у реальному часі?" — можна,
просто раніше цього не було реалізовано. Web Serial і так отримує байти
одразу по мірі надходження (`_readLoop()` безперервно дописує їх у
буфер) — проблема була лише в тому, що я показував накопичений вивід
ОДНИМ шматком, лише після повного завершення команди (чекаючи фінальний
маркер `\x04`).

Тепер `runStreaming()` перевіряє буфер кожні ~120мс і одразу передає нові
дані в консоль — і для коротких скриптів, і для `while True:` (вивід
з'являється по мірі появи `print()`, а не лише в кінці, якого може й не
бути). "⏹ Перервати" (Ctrl-C) можна натиснути в будь-який момент — плата
сама згенерує завершення (KeyboardInterrupt), і стрімінг коректно
закриється, показавши все, що встигло накопичитись.

Прибрано кнопку "🔁 Назавжди" (м'який перезапуск) — вона більше не
потрібна: тепер один "▶ Run" однаково добре підходить і для скриптів, що
завершуються самі, і для тих, що працюють вічно (просто натисніть "⏹
Перервати", коли досить).

Реалізовано саме так, як просили: реальний код бібліотек, яких немає у
прошивці MicroPython, тепер лежить у справжній теці `/libraries` проєкту
(не в localStorage браузера і не завантажується з мережі під час роботи).

  `libraries/umqtt/robust.py` — точні копії офіційних файлів з

  Python-синтаксису.
- `js/extensions/pico.js` бере код бібліотек САМЕ ЗВІДСИ (через
  `js/extensions/pico_libraries.js` — вбудований JS-бандл, потрібен через
  те, що `fetch()` локальних файлів блокується під `file://`, той самий

  канонічного джерела) → 3) нічого немає — модальне вікно підкаже
  імпортувати.
- Для `st7789`/`ili9341`/`lcd1602`/`bh1750`/`bmp280`/`mpu6050`/`hcsr04`/
  `servo`/`stepper`/`pca9685`/`sdcard` єдиного офіційного канонічного

  різне залізо) — підсунути "якусь одну" за стандартну було б нечесно.
  Для них лишився імпорт власного перевіреного .py (пояснено в
  `/libraries/README.md`).

## Розумний редактор коду + плиткова розкладка модулів/бібліотек

**Автозакриття забутих дужок**: якщо код закінчується незакритою дужкою
(наприклад `print("hello"` без `)`) — вона автоматично дописується
(правильним символом і в правильному порядку, навіть для змішаних типів
дужок), із поясненням у спливаючому сповіщенні. Виявлено і виправлено
реальний баг під час розробки — конфлікт імені змінної `stack` між новою
логікою дужок і старою логікою відступів (обидві використовували одну
й ту саму назву в одній функції) — перейменовано на `indentStack`.

**Розумні Enter/Tab/Backspace** у панелі коду:
- **Enter** після рядка, що закінчується на `:` — переходить у тіло
  конструкції з відступом (+4 пробіли до поточного).
- **Tab** вставляє відступ (4 пробіли) замість переходу фокуса з поля.
- **Backspace** на позиції серед самого лише відступу знімає ОДИН рівень
  відступу за раз (не по символу); коли відступу вже немає — стандартна
  поведінка (злиття з попереднім рядком).

**Плиткова розкладка** для вибору модулів (Turtle/Tkinter/Pico) і
бібліотек мікроконтролера — замість списку тепер сітка плиток із
векторними іконками (`assets/icons/*.svg`). Бібліотеки без реальних
блоків команд (urequests, umqtt, aioble, sdcard тощо) тимчасово
приховано зі списку — показуються лише ті 6, для яких є повноцінні
блоки (neopixel, ssd1306, lcd1602, dht, hcsr04, servo).
